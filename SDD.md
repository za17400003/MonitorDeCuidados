## 🏗️ ARQUITECTURA DEL SISTEMA

### Capa de Aplicación
- **App Única (`:app`) — Dual-Role**: Una sola APK con dos modalidades seleccionables al inicio:
  - **Modo Monitor (Cuidador)**: Gestiona la supervisión, alertas, visualización de video, control remoto de switches del Terminal.
  - **Modo Terminal (Persona Cuidada)**: Ejecuta CampanaService (detección de campana, voz, agitación, batería baja T53), muestra QR para vinculación, overlay de campana en lockscreen.
- **Selección de rol**: En onboarding (primera vez) o RoleSelectorActivity (cambio posterior). Se guarda en SharedPreferences como `app_mode` = "monitor" | "terminal".
- **Navegación por rol**: SplashActivity lee `app_mode` y redirige a MonitorMainActivity o TerminalMainActivity.
- **Evaluación geriátrica (T44)**: Los 3 puntos de entrada Terminal (OnboardingActivity, RoleSelectorActivity, SplashActivity) verifican `capabilities_status` en SharedPreferences. Si NO es "completed"/"omitted", redirigen a CapabilitiesAssessmentActivity antes de TerminalMainActivity.

### Capa de Comunicación (Protocolos)
- **Networking Local**: Uso de `NanoHTTPD` para servidores HTTP integrados en ambos dispositivos.
  - Puerto 8080: Comandos de control (JSON).
  - Puerto 9001: Streaming de video (UDP/Datagram).
  - Puerto 9000: Streaming de audio (UDP).
- **Descubrimiento de Dispositivos**: Implementación de `jMDNS` para detectar el Terminal en la red local automáticamente (`_caremonitor._tcp.local`).

### Capa de Datos (Persistencia Segura)
- **Base de Datos Local**: Room Persistence Library con cifrado **SQLCipher (AES-256)**.
  - Entidad `Event`: Log de alertas (campana, voz, sensores).
  - Entidad `Alarm`: Recordatorios programados con sincronización bidireccional.
  - Entidad `CustomPhrase`: Diccionario para reconocimiento de voz (ML Kit).
- **Preferencias**: `EncryptedSharedPreferences` para almacenar IPs de vinculación y secretos de emparejamiento.
- **Firestore (Cloud Sync)**: Backend NoSQL para sincronización multi-dispositivo, analytics y logs persistentes - **ESTRUCTURA COMPLETA**:

**Firestore Security Rules** (CRÍTICO - IMPLEMENTAR):
```
rules_version = '2';
service cloud.firestore {
  match /databases/{database}/documents {
    // Users can only read/write their own data
    match /users/{userId} {
      allow read, write: if request.auth.uid == userId;
    }
    
    // Pairings: read if involved, create if authenticated
    match /pairings/{document=**} {
      allow read: if request.auth != null && 
        (request.auth.uid == resource.data.monitorId || 
         request.auth.uid == resource.data.terminalId);
      allow create: if request.auth != null;
      allow update, delete: if false;
    }
    
    // Connection logs: append-only for authenticated users
    match /connection_logs/{document=**} {
      allow create: if request.auth != null;
      allow read: if request.auth != null;
      allow update, delete: if false;
    }
    
    // Call history: append-only
    match /call_history/{document=**} {
      allow create: if request.auth != null;
      allow read: if request.auth != null;
      allow update, delete: if false;
    }
    
    // Capabilities assessments: only own data
    match /capabilities_assessments/{document=**} {
      allow read, write: if request.auth != null && 
        request.auth.uid == resource.data.userId;
    }
    
    // Notifications history: append-only, read own
    match /notifications_history/{document=**} {
      allow create: if request.auth != null;
      allow read: if request.auth != null && 
        request.auth.uid == resource.data.userId;
      allow update, delete: if false;
    }
    
    // Localization: public read (for all languages)
    match /localization/{document=**} {
      allow read: if true;
      allow write: if false;
    }
    
    // Usage analytics: only own data
    match /usage_analytics/{document=**} {
      allow read, write: if request.auth != null && 
        request.auth.uid == resource.data.userId;
    }
  }
}
```

All ViewModels extend `androidx.lifecycle.ViewModel` and expose reactive state via `LiveData<T>` for automatic UI updates:

```kotlin
        is State.Loading -> showLoader()
        is State.Success -> updateUI(state.data)
        is State.Error -> showError(state.message)
    }
}
```

## 🌐 ARQUITECTURA DE NETWORKING (NUEVO - Marzo 20, 2026)

### 🔴 PRERREQUISITO CRÍTICO: EMPAREJAMIENTO
**⚠️ Monitor y Terminal SOLO se pueden emparejar VÍA QR**. No existe emparejamiento automático. El QR contiene JSON estructurado (CORREGIDO Marzo 30):
```json
{
  "deviceId": "UUID único del Terminal",
  "ip": "192.168.x.x",
  "port": 8080,
  "name": "Terminal de [Build.MODEL]",
  "secret": "CampanaSecureKey"
}
```
- `ip`: Obtenida con `isSiteLocalAddress()` para garantizar IP WiFi local (NO IP móvil)
- `deviceId`: UUID generado una vez y almacenado en SharedPreferences

Una vez emparejados vía QR, los dispositivos pueden establecer conexión. Este flujo ocurre EN CADA RECONNECTION.

### Priorización de Red: Local WiFi First

**Fase 1: Detección Local (Timeout: 3 segundos)** - ⚠️ SOLO PARA DISPOSITIVOS YA EMPAREJADOS
1. Monitor inicia mDNS broadcast buscando Terminal (`_monitor._tcp.local`) EN RED LOCAL
2. Si Terminal responde en misma red subnet → **LOCAL CONNECTION AVAILABLE** (usar puerto 8080/9000/9001)
3. Verificar que pairing token QR previo coincida con registro almacenado
4. Si QR token VÁLIDO → Establecer conexión local
5. Si QR token INVÁLIDO o expirado → Rechazar, mostrar QR nuevamente para re-emparejamiento obligatorio

**Fase 2: Fallback a Internet (Timeout: 15 segundos)** - Cuando Local NO disponible
1. Si mDNS no responde (=dispositivos en diferentes redes) → Fallback a Firestore
2. Verificar nuevamente que pairing token QR previo es VÁLIDO
3. Monitor envía `POST /establish_connection` a Firestore Cloud Function
4. Terminal recibe mensaje y establece conexión bidireccional via Firestore Realtime Database
5. Monitor y Terminal intercambian IPs públicas para futuras comunicaciones directas
6. Si pairing token INVÁLIDO → Conexión rechazada, requiere re-emparejamiento por QR

**Fase 3: Exponential Backoff (5s → 10s → 30s → 60s)** ✅ T54 implementado
1. TerminalDetailActivity.queryTerminalStatus() incrementa `consecutiveFailures` en cada fallo HTTP
2. Backoff: 1 fallo=5s, 2=10s, 3=30s, 4+=60s. Reset a 0 en éxito.
3. Si fallos superan 5 min → muestra "⚠️ Conexión perdida" en rojo
4. Al reconectar → restaura "✅ Conectado" y polling normal 5s

**Fase 4: Almacenamiento de Connection Type** ✅ T55 implementado
```kotlin
// NetworkUtils.kt — connection type tracking

fun getConnectionType(): String
fun setConnectionType(type: String, context: Context) // persiste en SharedPrefs

```

**Fase 5: Switchover Automático** ✅ T55 implementado
- TerminalDetailActivity: Si `consecutiveFailures > 6` y connectionType=="local" y hay internet → auto-switch a "internet"
- Al recibir respuesta exitosa estando en "internet" → auto-switch back a "local"
- CampanaService.onCreate() inicializa NetworkUtils + registra NetworkCallback
- CampanaService.onDestroy() desregistra NetworkCallback

### Protocolos de Comunicación por Network Type

**Local WiFi (Prioridad)**:
- mDNS broadcast: `_monitor._tcp.local:8080`
- Comandos JSON HTTP: Puerto 8080
- Consulta estado Terminal: GET `/status` Puerto 8080 (retorna JSON: batteryLevel, bellEnabled, shakeEnabled, voiceEnabled, alarmsEnabled, status, deviceName)
- Video streaming: UDP Datagram Puerto 9001 (JPEG fragmented)
- Audio streaming: UDP Datagram Puerto 5060 (OPUS codec, 16kHz, MediaCodec encoder/decoder)
- **Heartbeat**: TCP keepalive cada 10 segundos (detecta desconexión rápido)

**Internet Fallback**:
- Firestore Realtime Database (WebSocket vía Google's infrastructure)
- JSON messages routed through Firestore documents
- Video streaming: RTMP/RTSP through Firestore Cloud Storage signed URLs
- Audio streaming: Compressed OPUS over Firestore Realtime
- **Heartbeat**: Firestore onSnapshot listener (5 segundo max latency)

### Network Detection Algorithm (Pseudo-código)

```kotlin
class NetworkDetector {
  fun detectIfSameNetwork(): Boolean {
    // 1. Obtener IP local Monitor
    val monitorIP = NetworkUtils.getLocalIPAddress() // e.g., 192.168.1.100
    val monitorSubnet = monitorIP.substring(0, monitorIP.lastIndexOf(".")) // 192.168.1
    
    // 2. Resolver Terminal IP via mDNS
    val terminalIP = jmdns.resolveHost("terminal._tcp.local")?.hostAddress
    
    // 3. Si mDNS resuelve, verificar si ambos en mismo subnet
    if (terminalIP != null) {
      val terminalSubnet = terminalIP.substring(0, terminalIP.lastIndexOf("."))
      return monitorSubnet == terminalSubnet // true = misma red
    }
    return false // No resuelve = diferentes redes o sin WiFi local
  }
}
```

### 7B. Detección de Agitación (Shake Detection) - NUEVO Terminal-Only Feature (Marzo 29, 2026)

**Propósito**: Activar alerta de campana mediante agitación del dispositivo (acelerómetro) como alternativa a toque o voz.

**Alcance**: SOLO Terminal, independiente de lockscreen y voice detector.

**Implementación Técnica**:
- **Clase Principal**: `ShakeDetectionService.kt` (Service - background execution)
  - Extiende `Service` para ejecutarse incluso cuando la app está minimizada/cerrada
  - Registra SensorManager.TYPE_ACCELEROMETER en onCreate()
  - Implementa `SensorEventListener.onSensorChanged()` para capturar aceleración
  - Threshold: 12 m/s² (valor ajustable en preferencias)
  - Detecta dirección de shake en ejes X, Y, Z
  
- **Control Toggle**: Card 3 (`layout_terminal_config_content.xml`)
  - Switch "Activación por Agitación" (`switchShake`)
  - Android:id="@+id/switchShake"
  - Habilita/deshabilita servicio via `startService()` / `stopService()`

- **Persistencia**: SharedPreferences
  - Clave: "shake_detection_enabled" (boolean)
  - Se guarda al cambiar el switch
  - Se restaura al iniciar la app (verificar en TerminalConfigActivity)

- **Ejecución**:
  - Se inicia automáticamente si toggle está ON y CampanaService está activo
  - Requiere permisos: `android.permission.BODY_SENSORS` (declarar en AndroidManifest.xml)
  - Executa siempre que el usuario lo mantenga encendido y el servicio CampanaService esté activo
  - Sin importar si se agita dentro o fuera de la aplicación (background execution garantizado)

- **Flujo de Detección**:
  1. SensorManager captura eventos de acelerómetro continuamente
  2. onSensorChanged() calcula magnitud: √(x² + y² + z²)
  3. Si magnitud > threshold: Registra timestamp
  4. Si 2+ eventos en < 500ms: Considerar como "shake" válido
  5. Generar evento de alerta + Log en Event entity
  6. Enviar comando `/alert/shake` al Monitor vía CampanaHttpServer (puerto 8080)

- **Logging**:
  - Registrar cada shake detectado en Room Event entity: `event_type = "SHAKE"`
  - Timestamp y magnitud de aceleración

**Propósito**: Notificar al Monitor cuando la batería del Terminal cae por debajo del 15%.

**Alcance**: SOLO Terminal (monitoreo) + Monitor (recepción de alertas).

- **Threshold Logic**:
  - **Lower Threshold (Trigger)**: ≤15% (configurable en SettingsActivity: 10%, 15%, 20%, 25%)
  - **Upper Threshold (Release)**: >20% (hardcoded, no configurable)
  - **Reason**: 5% hysteresis para evitar spam si batería fluctúa entre 14-16%

  - Umbral personalizable: Spinner con opciones 10%, **15%**, 20%, 25% (clave: `battery_threshold_percent`)
  - Si toggle OFF: Terminal no envía eventos (pero sigue monitoreando)

- **Offline Queue**:
  - Si Terminal sin internet cuando batería baja: Evento se encola en Room (tabla Event)
